# 训练过程与结果总览（含可视化与演示方案）

## 1. 你这几天到底做了什么

本项目已经从“单一基线验证”升级为“多方法对抗平台”，核心完成内容包括：

1. 完成并稳定运行 Mini Amazons 对弈环境（6x6、移动+射箭阻塞规则）。
2. 形成多类型智能体体系：
   - 规则/搜索类：`Random`、`Heuristic`、`Minimax`、`MCTS`。
   - 学习类：`Q-learning`、`DQN(DoubleDQN)`、`A2C`、`PPO`、`BC from MCTS`、`AlphaZero-style`。
3. 打通完整工程闭环：
   - 自博弈训练 -> 模型保存 -> 批量评估 -> 图表生成 -> 文档沉淀。
4. 完成 GPU 训练环境落地（RTX 4060 + CUDA）。
5. 扩展可视化能力：训练曲线、矩阵热力图、排名图、对随机胜率置信区间图。

## 2. 训练过程是怎么推进的（按阶段）

### 阶段A：基线搭建与规则验证
- 先完成 Q-learning 自博弈和随机对照，确认代码闭环可运行。
- 验证状态表示、合法动作生成、终局判定与日志输出正确。

### 阶段B：深度学习方法接入
- 依次接入并跑通 `DQN -> A2C -> PPO`。
- 统一接口：都通过 `select_action(state, legal_actions)` 进行对弈。
- 增加模型保存、加载、跨方法互相对战评估。

### 阶段C：方法扩展（提升毕设工作量与研究深度）
- 增加 `MCTS` 作为搜索型强基线。
- 增加 `BC from MCTS`（教师-学生范式）。
- 增加 `AlphaZero-style`（MCTS + Policy/Value）分阶段训练。
- 形成“经典方法 + 深度强化学习 + 搜索结合学习”的完整对比框架。

### 阶段D：长程实验与统计版评估
- 完成 3000 局级别的长训练（DQN/A2C/PPO）。
- 完成 BC-long 与 AlphaZero Stage1/2/3。
- 输出 n=8、n=30、n=40 多级矩阵，逐步增强统计可信度。

## 4. 目前这些神经网络“水平如何”

结论（实事求是）：

1. 在当前 Mini Amazons 设定下，`A2C/PPO` 对随机有稳定提升，`DQN` 也有正提升。
2. 但整体上尚未稳定超过强规则/搜索基线（尤其 `Minimax`、`Heuristic`）。
3. `AlphaZero` 在当前训练预算和参数下处于“可用但未充分收敛”状态（Stage2 优于 Stage1/3）。
4. `BC from MCTS` 具备一定对抗能力，但仍需要更大教师数据和更长训练。

这在毕业设计里是合理且有价值的：
- 你不仅展示了“能训练”，还展示了“方法间差异、性能天花板、计算开销和改进方向”。
- 这类“有分析的负结果/中间结果”在研究报告中比只报高分更可信。

## 6. 除了“冷冰冰图表”，当前演示型可视化已落地什么

已落地，而且适合答辩展示。当前已提供“轻量可交互 Demo + 一键实验”。

### 方案A（当前主方案）：Streamlit 对弈界面
- 已有页面能力：
  1. 对弈页：智能体选择、单步/自动/终局执行、棋盘显示
  2. 日志回放页：回放滑条、案例导出（`results/cases`）
  3. 训练监控页：训练曲线 + `results/figures` 图像浏览（含关键词过滤）
  4. 一键实验页：一键训练、一键 Arena、一键出图、单按钮全流程
- 优点：开发快、部署简单、答辩交互强。

### 方案B：Pygame 本地棋盘演示
- 更像小游戏，视觉更直观，适合录屏展示。
- 但开发量略大于 Streamlit。

### 方案C：Web 前端（Vue/React）+ Python 后端
- 展示最专业，但开发成本最高，不建议在当前时间优先做。
